# Отчёт: dry-run контрольного прогона H23 (07.11)

**Цель:** до H23 пройти вживую путь «новый `group_id` → замена критерия → переоценка → экспорт», засечь время, найти грабли.
**Итог:** путь **работает целиком** через UI и через API. Найдено 10 подводных камней (вписаны в `CONTROL_RUNBOOK.md`)
и 9 багов/недочётов (ниже; код не правил — зона владельцев). Скрипт `deploy/h23_control.sh` проверен на всех исходах.

## Как проводили

- Проект из `cqa-share-v2.zip`, бэкенд как в README: `python3.12 -m venv .venv && .venv/bin/pip install -r requirements.txt`
  (13 с), `uvicorn app.main:app --port 8000`, база с нуля (`CQA_DATA_DIR` во временной папке), фронт — собранный `frontend/dist`.
- **API организаторов эмулировали** локальным сервером с тем же форматом ответа (`{"isSuccess":true,"data":{"dataset_group_id",
  "records":[…]}}`), потому что из песочницы dry-run подписанная ссылка недоступна. `CQA_API_URL` указывал на эмулятор — значит,
  импорт шёл **тем же кодом** (`datasource.fetch_group`, подстановка `group_id`, разбор, upsert). `DEV` → настоящие 65 записей;
  «контрольный» `group_id` → 10 записей (8 чатов + 2 звонка) с новыми ID `ctrl-001…010`.
- UI прогоняли настоящим браузером (Chrome, автоматизация кликов), время — по секундомеру скрипта. API — curl/python.
- Провайдер оценки — `mock` (ключа Claude в песочнице нет). Путь Claude проверен с **неверным** ключом (ошибка, время отказа).

## Что проверено и работает

| Сценарий | Результат |
|---|---|
| Импорт DEV и нового `group_id` через «Импорт из API» | «новых 10, обновлено 0», всего 75; повторный импорт идемпотентен, оценки не теряются |
| Импорт через `POST /api/datasets/import` | `{"dataset":…,"imported":10,"updated":0}` |
| План Б: «Загрузить JSON» (`/api/dialogs/upload`) с ответом API как есть | 200, записи загружены |
| Смена веса критерия (чаты) → «Сохранить» | новая версия, «используется для чатов»; веса перераспределяются (сумма 95 → ×100/95) |
| **Замена критерия целиком** (название + ID + инструкция) в чатах и звонках через UI | версии #4/#5; новый критерий `regulation` в оценках и в колонках CSV |
| Переоценка 1 диалога со страницы | по новой версии чек-листа своего канала |
| «Оценить выбранные (10)» по поиску | 10/10 |
| Пакет через API по списку ID, `reuse_unchanged` | смена только веса → **0 вызовов модели**; замена критерия → 1 суждение на диалог |
| Экспорт CSV/JSON (UI по фильтру и API `?ids=`) | ровно 10 записей; в CSV есть `provider`, `checklist_id`, колонки по критериям |
| Провайдер Claude с ключом в env | `available: true`, первым в переключателе для нового браузера |
| Claude с неверным ключом | 0.3 с → «все 5 прогонов не удались (HTTP 401 — invalid x-api-key)», в UI и API |
| Старт с «осиротевшими» `cqa_v2.db-wal/-shm` из архива | стартует нормально, сидирует 65 диалогов |
| Секреты в архиве | подписанных ссылок и ключей нет (`server.log` содержит только адреса api.anthropic.com) |

Тайминги — таблица в `CONTROL_RUNBOOK.md` (всё на mock укладывается в 0.1–4 с; на сцене решает ручной ввод и время Claude).

## Баги и недочёты (для владельцев кода — не исправлял)
