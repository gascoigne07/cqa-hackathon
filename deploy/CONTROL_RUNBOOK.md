# H23 · Контрольный набор и замена критерия — runbook

На 23-м часе организаторы дают **новый `group_id`** (10 контрольных транскриптов) и просят **заменить один критерий**.
Путь целиком прогнан dry-run 07.11 на копии проекта (результаты и тайминги — в конце и в `deploy/DRYRUN_H23.md`).

**Живой URL:** <https://cqa-web-production.up.railway.app>  ·  ведущий за клавиатурой + второй следит за API/таймером.

## 1. Импорт контрольного набора (≈ 15 с)

**UI:** «Диалоги» → **«Импорт из API»** → `group_id` = значение от организаторов → **«Импортировать»**.
Ожидаем зелёное сообщение: **«Набор `<group_id>`: новых 10, обновлено 0.»**

**API:**
```bash
curl -sS -X POST "$BASE/api/datasets/import" -H 'Content-Type: application/json' -d '{"group_id":"<group_id>"}'
# → {"dataset":"<group_id>","imported":10,"updated":0}
```

- **«обновлено» > 0** — ID контрольных диалогов совпали с уже загруженными; их старые оценки относятся к старому тексту → обязательно переоценить.
- **Ошибка «Неизвестный формат: ожидается ответ API…»** обычно означает неверный `group_id` (API вернул `isSuccess:false`, а сообщение API теряется — см. баг №1 в отчёте). Перепроверить значение, нажать ещё раз.
- **План Б**, если API организаторов не отвечает: попросить у них JSON → «Загрузить JSON» (проверено, принимает ответ API как есть).
- Новые диалоги появляются **в конце списка**. Фильтра по набору нет — ищем по общей части ID (поле «Поиск»).

## 2. Оценка контрольного набора (UI ≈ 10 с + время модели)

**UI:** «Диалоги» → «Поиск» = общая часть ID контрольных диалогов → кнопка становится **«Оценить выбранные (10)»** → нажать.

**API (если у ID нет общей части, или для скорости):**
```bash
GROUP=<group_id> bash deploy/h23_control.sh          # импорт → оценка только этих 10 → CSV+JSON → проверка
```

> ⚠ **Не нажимать «Применить ко всем диалогам»** (вкладка «Чек-лист») — она переоценивает **все** диалоги базы, включая 65 DEV.
> В dry-run: 75 диалогов, **530 новых суждений модели**. На Claude (5 прогонов на диалог) это ~375 платных запросов и минуты ожидания на сцене.

## 3. Замена критерия (≈ 3–6 мин руками, сохранение ≈ 2 с)

1. Вкладка **«Чек-лист»** → в списке **«Версия»** выбрать **чек-лист ЧАТОВ** («… (для чатов) · используется»).
   ⚠ По умолчанию открывается **самая новая версия**, обычно это чек-лист **звонков** или копия «smoke test» (канал «all» — её правка ни на что не повлияет).
2. Найти критерий → стрелка «›» справа → поменять **Название**, **ID** (латиницей, напр. `regulation`), **Инструкция для модели**, при необходимости тип/шкалу/N/A и **Вес** в строке.
3. **«Сохранить чек-лист»** → внизу «Сохранено как #N — используется **для чатов**».
4. **Повторить 1–3 для чек-листа ЗВОНКОВ.** ⚠ В dry-run правка только чатов → звонки оценились по **старому** чек-листу (в контрольном наборе обычно есть звонки).
5. Проверка: в выпадающем списке «Версия» у обеих новых версий пометка «используется».

## 4. Переоценка после замены (быстрый путь)

**Лучше всего — только изменённый критерий и только контрольные диалоги:**
```bash
GROUP=<group_id> SKIP_IMPORT=true REUSE=true bash deploy/h23_control.sh
```
Модель судит заново **только новый критерий**; остальные 7 ответов берутся из прошлой оценки **того же провайдера**
(в dry-run: 10 диалогов, 0 новых суждений при смене только веса; 1 критерий на диалог при замене критерия).
Смена **только веса** не требует вызова модели вовсе — итог пересчитывается мгновенно.

**UI-вариант:** «Диалоги» → «Поиск» → «Оценить выбранные (10)» — переоценивает **все 8 критериев** (дольше на Claude, но надёжно).
Флажок «Переоценить только изменённые критерии» есть только у кнопки «Применить ко всем диалогам» (см. ⚠ выше).

## 5. Экспорт (≈ 5 с)

**UI:** «Диалоги» → «Поиск» по контрольным ID → кнопки **CSV** / **JSON** над таблицей (выгружается **только отфильтрованное**).
**API:** уже сделано скриптом (`control-<group>-<время>.csv/.json`), либо
```bash
curl -o control.csv "$BASE/api/export?format=csv&ids=<id1>,<id2>,…"
```

> ⚠ **Перед сдачей проверить колонку `provider` = `claude` у всех 10 строк.** Если оценка Claude не удалась, в выгрузку
> **молча** попадает прошлая оценка (в dry-run — от `mock`). Скрипт `h23_control.sh` проверяет это сам (шаг 5) и завершится с ошибкой.

## Подводные камни (найдены в dry-run)

1. **Правка чек-листа действует только на свой канал.** Чаты и звонки — разные чек-листы; менять оба.
2. **Вкладка «Чек-лист» открывает самую новую версию**, а не чек-лист чатов. Всегда выбирать версию в «Версия».
3. **«Применить ко всем диалогам» = все диалоги базы**, включая DEV. Для контроля — только «Оценить выбранные» или скрипт.
4. **Неудачная оценка не видна в выгрузке**: остаётся предыдущая (возможно, mock). Проверять колонку `provider`.
5. **Переиспользование ответов работает только в пределах одного провайдера.** Если контроль сначала оценили на mock,
   «только изменённые» на Claude ничего не переиспользует — будет полная оценка.
6. **Выбор модели в шапке запоминается браузером.** На демо-ноутбуке проверить, что нажато «Облако · Claude».
7. **Любая смена Variables на Railway = перезапуск = SQLite стирается** (импорт контроля, правки чек-листа, оценки, апелляции).
   Переключать провайдера **до** H23, возвращать — **после** экспорта.
8. **Нет фильтра по набору** в списке диалогов: если у контрольных ID нет общей части, работать через `h23_control.sh`.
9. Сообщение об ошибке при неверном `group_id` не показывает ответ API (см. отчёт, баг №1).
10. Если кто-то запускал `deploy/smoke_test.py` на живом URL — в «Чек-листе» первой открывается копия «smoke test» (канал «all»):
    её правка **не применится** ни к чатам, ни к звонкам. Сброс: `railway redeploy` (но см. п. 7).

## Если что-то пошло не так

| Симптом | Что делать |
|---|---|
| Импорт: «API ответил 4xx/5xx» или таймаут (60 с) | повторить; затем план Б — JSON от организаторов → «Загрузить JSON» |
| Claude: «все 5 прогонов не удались … 401» | ключ неверный/отозван → новый ключ в Variables (≈ 1–2 мин перезапуск, затем импорт и правки заново) |
| Claude: 429 / медленно | ждать (3 повтора встроены); при необходимости `CQA_CONCURRENCY=2` (тоже перезапуск) |
| Оценка висит | проверить `GET $BASE/api/score/batch/<job_id>`; оценивать по 1–2 диалога со страницы диалога |
| Сайт не открывается | `railway logs --service cqa-web`; запасной — локально: `docker run -p 8000:8000 --env-file backend/.env cqa` |
