# H23 · Контрольный набор и замена критерия — runbook

На 23-м часе организаторы дают **новый `group_id`** (10 контрольных транскриптов) и просят **заменить один критерий**.
Весь путь делается **в интерфейсе**, без поиска по ID:

> **Импорт → выбрать набор в фильтре → «Оценить выбранные (10)» → экспорт.**
> После замены критерия: **«Применить к диалогам…» → тот же набор** (отдельно для чатов и для звонков).

Путь прогнан в dry-run 07.11 и повторно 08.11 на копии v4: эмулятор API, провайдер `mock`. Тайминги — в конце, подробности — в `deploy/DRYRUN_H23.md`.

**Живой URL:** <https://cqa-web-production.up.railway.app>. Один человек ведёт за клавиатурой, второй следит за таймером и API.
`BASE=https://cqa-web-production.up.railway.app`

## 1. Импорт (≈ 15 с)

«Диалоги» → **«Импорт из API»** → `group_id` от организаторов → **«Импортировать»**.

Ожидаем: **«Набор `<group_id>`: новых 10, обновлено 0. Показан только этот набор (остальные фильтры сброшены).»**
В таблице сразу видны **только 10 контрольных**, поиск, язык, канал и «Только грубые ошибки» сброшены, кнопка — **«Оценить выбранные (10)»**.

- **«API организаторов вернул ошибку: … — проверьте group_id»** — опечатка в `group_id`. Исправить и нажать ещё раз.
- **«обновлено» > 0** — ID совпали с уже загруженными. Старые оценки относятся к старому тексту, поэтому шаг 2 обязателен.
- **План Б** (API не отвечает): JSON от организаторов → **«Загрузить JSON»**. Набор тоже покажется сам.

## 2. Оценка (≈ 10 с руками + время модели)

Проверить три вещи: **«Набор» = `<group_id>`**, переключатель **«Только грубые ошибки» выключен**, кнопка показывает **(10)**.
Затем → **«Оценить выбранные (10)»** → ждать «Готово 10 из 10».

Для демо после оценки можно включить **«Только грубые ошибки»**: строка покажет причину, клик откроет разбор на нужной реплике.
**Перед шагами 4–5 переключатель выключить.**

> ⚠ Кнопка оценивает **ровно то, что видно в таблице**. Если включён «Только грубые ошибки» или заполнен «Поиск», в счётчике будет меньше 10.

## 3. Замена критерия (≈ 3–6 мин руками)

1. «Чек-лист» → **«Версия»** → выбрать **«… (для чатов) · используется»**. По умолчанию открывается самая новая версия, а это может быть чек-лист звонков.
2. Найти критерий → «›» → поменять **Название**, **ID** (латиницей), **Инструкцию для модели**, при необходимости тип, шкалу, N/A и **Вес**.
3. **«Сохранить чек-лист»** → «Сохранено как #N — используется для чатов».
4. **Повторить 1–3 для «… (для звонков)».** В контрольном наборе обычно есть и звонки.

## 4. Переоценка после замены (≈ 15 с руками + модель)

Сразу после сохранения, на той же вкладке:

1. Флажок **«Переоценить только изменённые критерии»** оставить включённым.
2. **«Применить к диалогам…»** → **«Набор диалогов» = `<group_id>`** → **«Переоценить N»**.
   N — это только диалоги **этого канала** из набора (в dry-run: 7 чатов).
3. То же для чек-листа звонков (в dry-run: 3 звонка).

Модель заново судит **только изменённый критерий**, остальные ответы берутся из прошлой оценки **того же провайдера**.
Смена одного веса — **0 вызовов модели**, итог пересчитывается мгновенно.

> ⚠ В окне «Применить» **не оставлять «Все наборы»**: тогда переоценятся и все DEV-диалоги этого канала.

## 5. Экспорт (≈ 5 с)

«Диалоги» → **«Набор» = `<group_id>`**, «Только грубые ошибки» **выключен** → **CSV** / **JSON**. Выгружается только то, что в таблице: 10 строк.

> ⚠ Если над таблицей жёлтое **«N из 10 диалогов не оценены моделью «Облако · Claude»»** — эти N оценены другой моделью
> или не оценены вовсе. Переоценить их (шаг 2) **до** выгрузки. Перед сдачей проверить колонку `provider` = `claude` у всех 10 строк.

## Подводные камни

1. **Чаты и звонки — разные чек-листы.** Менять и переоценивать оба (шаги 3–4 дважды).
2. **«Чек-лист» открывает самую новую версию**, а не чек-лист чатов. Версию всегда выбирать явно.
3. **Кнопки оценки и экспорта работают по видимой таблице.** Фильтры «Набор», «Язык», «Канал», «Поиск» и «Только грубые ошибки» сужают её.
   Перед оценкой и экспортом проверить: набор = контрольный, остальные фильтры = «Все», переключатель выключен.
4. **Неудачная оценка не видна в выгрузке**: остаётся предыдущая. Жёлтое предупреждение над таблицей и колонка `provider` это показывают.
5. **«Только изменённые» переиспользует ответы только той же модели.** Если контроль сначала оценили на mock,
   на Claude будет полная оценка.
6. **Выбор модели в шапке запоминается браузером.** На демо-ноутбуке проверить «Облако · Claude».
7. **Любая смена Variables на Railway = перезапуск = SQLite стирается.** Переключать провайдера **до** H23, возвращать **после** экспорта.
8. Если на живом URL запускали `deploy/smoke_test.py`, в «Чек-листе» первой открывается копия «smoke test» (канал «all»).
   Её правка не применится ни к чатам, ни к звонкам. Выбирать версии «для чатов» и «для звонков».

## Если что-то пошло не так

| Симптом | Что делать |
|---|---|
| Импорт: «API ответил 4xx/5xx» или таймаут (60 с) | повторить; затем план Б — JSON от организаторов → «Загрузить JSON» |
| Claude: «все 5 прогонов не удались … 401» | ключ неверный или отозван → новый ключ в Variables (перезапуск ≈ 1–2 мин, затем импорт и правки заново) |
| Claude: 429 или медленно | ждать (3 повтора встроены); при необходимости `CQA_CONCURRENCY=2` (тоже перезапуск) |
| Оценка висит | `GET $BASE/api/score/batch/<job_id>`; оценивать по 1–2 диалога со страницы диалога |
| Сайт не открывается | `railway logs --service cqa-web`; запасной вариант — локально: `docker run -p 8000:8000 --env-file backend/.env cqa` |
