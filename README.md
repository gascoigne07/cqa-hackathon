# CQA — Conversation Quality Analytics

Прототип оценки качества работы операторов для хакатона Freedom Broker.
Пользователь настраивает чек-лист, запускает живую оценку диалога выбранной
моделью (облако Gemini / локальная Qwen3), видит баллы, обоснования и
реплики-доказательства, подаёт апелляцию; проверяющий подтверждает или меняет
оценку, итог пересчитывается.

**API-контракт команды — в [CONTRACT.md](CONTRACT.md).** Фронтенд работает
только через него; бэкенд в этом репозитории — его полная реализация.

> **Статус:** сайт работает полностью. Провайдеры Gemini и Qwen3 подключает
> ML-команда (один метод на провайдер, см. ниже) — до этого они видны в
> переключателе как недоступные, а оценки ставит **демо-провайдер** на ключевых
> словах. Встроены два чек-листа: **официальный для чатов** (из PDF организаторов,
> 8 критериев, веса 10/15/20/20/15/15/5/0, округление до 2 знаков) и **для звонков** —
> адаптация по разъяснению организаторов (те же критерии и веса; №4 и №6 под устную речь).

## Быстрый старт

Нужен Python 3.10+. Node.js нужен только для правки интерфейса (собранный
интерфейс уже лежит в `frontend/dist`).

```bash
./start.sh
```

Откройте <http://localhost:8000>. При первом запуске подхватываются 65 диалогов
DEV из `backend/data/dev.json` и создаются чек-листы для чатов и для звонков.

### Режим разработки

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r backend/requirements.txt
cp backend/.env.example backend/.env            # заполните CQA_API_URL и ключи провайдеров
cd backend && uvicorn app.main:app --reload     # http://localhost:8000, docs: /docs

cd frontend && npm install && npm run dev       # http://localhost:5173, /api проксируется на :8000
```

## Сценарий демонстрации (5 минут)

1. **Интерфейс и диалог.** Список: id, канал, язык, число реплик, превью. В шапке —
   переключатель модели (Облако · Gemini / Локально · Qwen3).
2. **Оценка.** «Оценить» → живой разбор выбранной моделью. По каждому критерию:
   вердикт/балл, вес, доля в итоге, объяснение, цитата. Клик по цитате прыгает к
   реплике и подсвечивает её; у звонков — перематывает запись, а во время
   воспроизведения подсвечивается текущая реплика. N/A — с причиной и
   перераспределённым весом. Грубая ошибка — красный бейдж. Внизу — итоги секций и общий балл.
3. **Апелляция.** «Оспорить» (критерий + комментарий) → вкладка «Апелляции»: спорная
   оценка, комментарий, фрагмент → «Изменить оценку» + причина → пересчёт. В карточке:
   исходная → решение → финал, исходный итог сохраняется.
4. **Смена критерия.** «Чек-лист» — компактная таблица: строка на критерий, веса
   правятся прямо в строке, полоса показывает доли секций. Шеврон раскрывает остальное
   (название, секция, тип Да-Нет / Да-Нет-N/A / шкала, ступени шкалы, инструкция модели);
   порядок, канал и общие правила — там же → «Сохранить» → «Применить ко всем
   диалогам». Чатам достаётся новейший чек-лист для чатов, звонкам — для звонков. С галочкой
   «только изменённые» модель вызывается лишь для изменённых критериев.

## Подключение моделей

**Без кода — просто ключ в `backend/.env`** и перезапуск `./start.sh`:

| Провайдер | Что вписать | Кнопка в переключателе |
|---|---|---|
| **Claude (облако, по умолчанию)** | `CQA_ANTHROPIC_API_KEY`, при желании `CQA_ANTHROPIC_MODEL` (деф. `claude-sonnet-5`) | «Облако · Claude» |
| OpenAI (облако, для тестов) | `CQA_OPENAI_API_KEY`, при желании `CQA_OPENAI_MODEL` | «Облако · OpenAI» |
| Groq (облако, есть Qwen3) | `CQA_GROQ_API_KEY`, при желании `CQA_GROQ_MODEL` | «Облако · Groq» |
| Локальная Qwen3 | `ollama pull qwen3:8b`, затем `CQA_QWEN_BASE_URL=http://localhost:11434/v1` | «Локально · Qwen3» |

Все три работают через один OpenAI-совместимый клиент (`OpenAICompatScorer`): temperature 0,
JSON-режим, повтор при 429/5xx, теги `<think>` у Qwen3 отбрасываются. OpenAI и Groq скрыты в
переключателе, пока для них нет ключа.

**Claude — основной провайдер (реализован):** `ClaudeScorer` в `backend/app/scorers/llm.py`
(Anthropic Messages API) с **self-consistency**: на каждый диалог делается `CQA_CLAUDE_SAMPLES`
(по умолчанию 5) параллельных прогонов, итог — большинство по вердиктам и медиана по шкалам.
Это убирает разброс одиночного вызова (одна оценка «гуляла» на 15–30 баллов; голосование из 5 —
±0–6) и даёт **MAE ~7.58** против ручного эталона из 35 диалогов (детали — на экране «Точность»).

**Gemini — свободный слот:** при желании реализуйте `GeminiScorer._complete` по аналогии и задайте
`CQA_GEMINI_API_KEY` (промпт и разбор уже готовы в `scorers/prompt.py`).

**Доказательство живого анализа:** у каждой оценки сохраняются модель, время, число вызовов и
токены, а кнопка «Запрос к модели» показывает точный промпт и сырой ответ модели.

**Экспорт:** кнопки «CSV» / «JSON» в списке диалогов — последняя оценка каждого диалога
(с учётом фильтров), по критерию: вердикт и баллы. Удобно сверять с эталоном. Контракт суждения — в
`scorers/base.py`: цитировать реплики по `idx`, при отсутствии действия возвращать
`checked_range`, N/A только где разрешено, судить оператора, а не бота.
**Не передавайте модели имя оператора и его прошлые оценки** — это смещает вердикты.

**Стоимость одной оценки.** Модель по умолчанию — **claude-sonnet-5** с голосованием из 5
прогонов (`CQA_CLAUDE_SAMPLES`). Цена **с учётом всех 5 вызовов** по прайсу Sonnet
($3 / 1М входных токенов, $15 / 1М выходных), замерено по трейсу:
- чат (~12 реплик): ~14.4К входных + ~9.3К выходных токенов → **≈ $0.18** за оценку;
- звонок (длинный транскрипт): ~25.3К + ~15.0К токенов → **≈ $0.30** за оценку.

Удешевление без правок кода: `CQA_CLAUDE_SAMPLES=1` → примерно в 5 раз дешевле (~$0.04, но менее
стабильно); локальная Qwen3 → **$0**. Весь набор (65 диалогов) ≈ $12–16 — покрывается месячным
кредитом Claude Max, то есть на хакатоне фактически **бесплатно**.

## Как считается итог

Модель только выносит суждения. Числа считает `backend/app/scoring.py` (покрыт тестами):
нормализация (да = 1, нет = 0, шкала → доля от максимума), N/A исключается и его вес
перераспределяется, `points = доля × балл`, `total = Σ points`, секции — `points / max`,
критерии с весом 0 (официальные «Грубые ошибки») баллов не дают, грубая ошибка — ответ
критерия, совпавший с его `gross_error_if` («Да» у «Грубых ошибок»), округление ROUND_HALF_UP до 2 знаков.
Подробно — в CONTRACT.md. Каждая цитата проверяется: реплика должна существовать, текст —
совпадать; иначе критерий переспрашивается, затем помечается «нужна проверка».

## Данные

- «Импорт из API» (`group_id=DEV`, на H23 — от организаторов) — запрос делает бэкенд, CORS не мешает.
- «Загрузить JSON» — формат организаторов.
- Записи звонков: `audio_url` организаторов — HTML-страница плеера с MP3-ссылкой на ~1 час;
  бэкенд скачивает MP3 и отдаёт его сам. Позиция в записи приблизительная (вычтены паузы при удержании).

## Dynamics 365

- Все запросы — через `frontend/src/api/transport.ts`; для встраивания нужна новая
  реализация транспорта (например, `Xrm.WebApi`), экраны не меняются.
- `npm run build:webresource` → один файл `frontend/dist-webresource/cqa.html` для HTML web resource;
  адрес API: `<script>window.CQA_API_BASE = "https://…"</script>`.
- Маршруты через `#/…` — работают в iframe и из одного файла. UI на Fluent UI v9.

## Стек

FastAPI + Pydantic + SQLAlchemy (SQLite WAL; Postgres через `CQA_DB_URL`), SSE для
прогресса. React 18 + TypeScript + Vite (статик-билд, без SSR), Fluent UI v9,
TanStack Query, wavesurfer.js. Типы контракта — `frontend/src/api/contract.ts`.

## Ограничения

- Gemini ждёт реализации `_complete`; OpenAI/Groq/Qwen3 включаются ключом или адресом в `.env`.
  Демо-провайдер — не модель качества.
- Чек-лист для звонков — наша адаптация по письму организаторов (отдельного PDF для звонков нет).
- Перемотка записи приблизительная.
- Авторизации нет (по ТЗ); апелляция и решение — отдельные действия в интерфейсе.
